## Обзор

Каждая SEO-статья проходит 5 шагов. Автоматизированы: написание, гуманизация, аудит.
Ручная проверка: только факты + финальный вид (HTML в браузере).

```
 1. ИССЛЕДОВАНИЕ
    │
    ▼
 2a. НАПИСАНИЕ ─── seo-content-writer
    │
    ▼
 2b. ГУМАНИЗАЦИЯ ─── De-AI-fy + SEO constraint
    │
    ▼
 2c. АУДИТ ─── content-quality-auditor (80 items CORE-EEAT)
    │
    ├── SHIP → идём на шаг 3
    ├── FIX  → правлю → показываю пользователю (шаг 3)
    └── BLOCK → правлю критическое → перезапускаю аудит (макс. 2 раза)
    │         └── 2 BLOCK подряд → показываю пользователю, решаем вместе
    │
    ▼
 3. ПОКАЗ ПОЛЬЗОВАТЕЛЮ
    HTML в браузере + отчёт (SEO score + факты с источниками)
    │
    ├── ОК → деплой
    └── Правки → исправляю → показываю снова (макс. 3 раунда)
              └── 3 раунда правок → пересматриваем тему/угол статьи
    │
    ▼
 4. ДЕПЛОЙ
    sitemap.xml + git push + переобход в Вебмастере
```

## Шаг 1: Исследование

**Инструмент:** Exa MCP (web_search_exa, web_search_advanced_exa).
**Fallback:** Если Exa недоступен — WebSearch. Сообщить пользователю о замене.

**Что делаю:**
- Поиск по русскоязычным и англоязычным источникам
- Официальные сайты (CAPLE, законодательство)
- Форумы и реальный опыт
- Конкуренты в топе по целевому запросу

**Дополнительно для грамматических тем:**
- Можно использовать учебники, включая «Basic Portuguese A Grammar and Workbook» (PDF в проекте)
- **ОБЯЗАТЕЛЬНО:** Перед использованием любого учебника как источника — спросить у пользователя разрешение
- Учебник = источник фактов и примеров, НЕ копировать текст дословно

**Артефакт:** `research/тема-facts.md` — справка с фактами и ссылками на источники.

**Правила:**
- Каждый факт — с источником (URL или название учебника + страница)
- Противоречия между источниками — отмечать явно
- Не выдумывать цифры — если нет данных, писать «не подтверждено»
- **ПРАВИЛО ПЕРВИЧНОЙ ВЕРИФИКАЦИИ:** Если факт ссылается на конкретную страницу (FAQ, документ, закон) — ОБЯЗАТЕЛЬНО открыть эту страницу (WebFetch) и подтвердить, что факт там действительно есть. Нельзя доверять вторичным источникам, которые пишут «confirmed by X» — нужно зайти на X и проверить самому. В research-файле отмечать:
  - ✅ **Проверено на первоисточнике** — открыл страницу, факт подтверждён
  - ⚠️ **Из вторичного источника** — так пишут prep2go/ciple.org, первоисточник не проверен

## Шаг 2a: Написание — seo-content-writer

**Скилл:** `~/.agents/skills/seo-content-writer/`

**Входные данные:**
- Файл-справка из шага 1
- Целевой ключевой запрос (primary keyword)
- 3-5 вторичных ключей
- Тип контента (guide / comparison / listicle)
- CTA: deep link на конкретный урок (см. правила CTA ниже)

**Что делает скилл:**
- Keyword map (primary в H1, first 100 words, H2, conclusion)
- Структура: H1 → H2 → H3, FAQ, таблицы
- Title (до 60 символов) + meta description (до 160 символов)
- Internal links: на `/` (лендинг) + другие статьи (если есть)
- External links: 2-3 авторитетных источника
- Self-check по 16 CORE-EEAT критериям

**Объём:** 1500-2000 слов.

**Артефакт:** `тема/index.html` (черновик).

## Шаг 2b: Гуманизация — De-AI-fy

**Скилл:** De-AI-fy (4 параллельных критика + рерайт)

**Критики:**
1. **Generic Detector** — AI-шаблонные фразы
2. **Rhythm Analyzer** — однообразная длина предложений
3. **Specificity Checker** — где добавить конкретику
4. **Fact Checker** — проверка claims через web search

**SEO constraint (добавляется к стандартным правилам):**
```
PRESERVE these SEO elements — do NOT rephrase or remove:
- Primary keyword in H1 tag (exact match)
- Primary keyword in first 100 words
- Primary keyword in at least one H2
- Meta description text
- FAQ questions and answers (Schema.org source)
- Internal links and their anchor text
```

**Правила рерайта:**
- Output ≤ original word count
- Vary sentence length (3-word и 20-word mix)
- Kill generic phrases
- Add 1 personal touch
- Break 1 grammar rule (начать с «И» или «Но», фрагмент)

**Артефакт:** обновлённый `тема/index.html`.

## Шаг 2c: Аудит — content-quality-auditor

**Скилл:** `~/.agents/skills/content-quality-auditor/`

**Что проверяет:**
- 80-item CORE-EEAT benchmark (8 измерений × 10 items)
- GEO Score (CORE) + SEO Score (EEAT)
- Veto checks (T04, C01, R10)
- Weighted score по типу контента

**Вердикты:**
| Вердикт | Действие |
|---------|----------|
| **SHIP** | Идём на шаг 3 (показ) |
| **FIX** | Правлю по рекомендациям → показываю пользователю |
| **BLOCK** | Правлю критическое → перезапускаю аудит (макс. 2 раза, потом эскалация к пользователю) |

**Важно:** После правок НЕ перезапускаю De-AI-fy. Правки точечные — показываю результат пользователю напрямую.

## Шаг 3: Показ пользователю

**Как:**
- Запускаю `py -m http.server 8080` в папке course
- Пользователь открывает `http://localhost:8080/тема/` в браузере
- Вижу финальный HTML со всеми стилями

**Отчёт (в чате):**
- SEO score из аудита
- Список ключевых фактов для проверки (5-10 пунктов с URL-источниками)
- Что было исправлено на шагах 2b-2c

**Пользователь проверяет:**
- Фактическая точность (по ссылкам на источники)
- Стиль и тон (не звучит ли как AI)
- Визуальный вид (картинки, таблицы, вёрстка)

**Решение:** ОК → деплой. Правки → исправляю → показываю снова (макс. 3 раунда, потом пересматриваем тему/угол).

---

## Шаг 4: Деплой

1. Обновить `sitemap.xml` (новый `<url>` с `<lastmod>` и `<changefreq>weekly`)
2. `git add` + `git commit` + `git push` (автодеплой на Cloudflare Pages)
3. Обновить счётчик статей в этом файле (секция «Счётчик статей и перелинковка»)
4. Если счётчик = 3, 6, 9... → напомнить пользователю о перелинковке
5. **Автоматически:** Яндекс Webmaster API → переобход конкретного URL (приоритетная очередь)
6. **Автоматически:** Google sitemap ping → `curl "https://www.google.com/ping?sitemap=https://learn-portugues.ru/sitemap.xml"`

## HTML-шаблон статьи

Каждая страница — standalone HTML. Включает:

**Head:**
- Lunaris DS CSS-переменные (те же что на лендинге)
- `css/articles.css` (общие стили для статей)
- Шрифты: JetBrains Mono + Geist (Google Fonts)
- Яндекс.Метрика (счётчик 108518143)
- OG + Twitter Card мета-теги
- Canonical URL: `https://learn-portugues.ru/{url-slug}/` (транслитерация, напр. `ciple-a2`)
- Schema.org: Article + FAQPage (JSON-LD)

**Body:**
- Header: лого + «← На главную»
- Article: prose-стили (H1, H2, H3, абзацы, таблицы, списки, blockquote)
- Картинки: Unsplash (утверждаются пользователем в ревью). Обязательно с описательным `alt` текстом
- CTA-блок (см. «Правила CTA» ниже)
- FAQ с аккордеоном (как на лендинге)
- Footer: такой же как на лендинге

## Правила CTA (ссылка на курс)

Каждая статья содержит CTA-блок «Попробуйте в курсе». Ссылка зависит от темы:

**Если статья связана с конкретным уроком:**
- Ссылка ведёт на `/course/#/lesson/N` (где N — номер урока)
- Пример: статья про артикли → `/course/#/lesson/2` (Unit 2: Articles)
- После авторизации пользователь попадает сразу на нужный урок

**Если статья общая (CIPLE, «как выучить», сравнение):**
- Ссылка ведёт на `/` (лендинг)
- Лендинг сам ведёт на курс

**Маппинг статей → уроков:**

| Статья | Урок | URL |
|--------|------|-----|
| CIPLE A2 | общая | `/` |
| Португальский или испанский | общая | `/` |
| Артикли | Unit 2 | `/course/#/lesson/2` |
| Ser и estar | Unit 5 | `/course/#/lesson/5` |
| Спряжения | Unit 4 | `/course/#/lesson/4` |
| Числа | Unit 3 | `/course/#/lesson/3` |

## Яндекс Webmaster API (автоматический переобход)

**Статус:** ✅ Настроено (2026-04-14). Токен в `.env`, квота 150 URL/день.

**Использование при деплое (Claude читает `.env` и выполняет):**

```bash
# Загрузить переменные
source .env

# Переобход конкретного URL
curl -s -X POST \
  -H "Authorization: OAuth $YANDEX_WEBMASTER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://learn-portugues.ru/{slug}/"}' \
  "https://api.webmaster.yandex.net/v4/user/$YANDEX_WEBMASTER_USER_ID/hosts/$YANDEX_WEBMASTER_HOST_ID/recrawl/queue"
```
