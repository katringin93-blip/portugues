5. **Только 4 URL в sitemap** — тонкий сайт для поисковиков

- Добавить canonical на privacy/terms

## 1. Crawlability & Indexation

### 1.1 robots.txt — КОНФЛИКТ с Cloudflare

**Impact: HIGH**

Cloudflare вставляет свой блок **перед** вашими правилами:

```
# Cloudflare Managed:
User-agent: *
Content-Signal: search=yes,ai-train=no
Allow: /

User-agent: ClaudeBot
Disallow: /
User-agent: GPTBot
Disallow: /
...

# Ваши правила (ниже):
User-agent: *
Allow: /
Disallow: /course/js/
Disallow: /course/css/
Sitemap: https://learn-portugues.ru/sitemap.xml
```

**Проблемы:**
- Два блока `User-agent: *` — по RFC 9309 правила мержатся, но некоторые парсеры берут только первый блок → ваши `Disallow` для `/course/js/` и `/course/css/` могут игнорироваться
- `Sitemap:` директива в конце может не попасть в парсинг некоторых ботов
- Cloudflare блокирует Amazonbot, Bytespider — это ОК, но нужно знать об этом

**Fix:** В Cloudflare Dashboard → Security → Bots → AI Crawlers — проверить настройки. Либо добавить `Sitemap:` директиву в начало вашего блока robots.txt. Как альтернатива — добавить sitemap через `_headers` или через `<link rel="sitemap">` в HTML.

### 1.2 Sitemap — тонкий

**Impact: MEDIUM**

Только 4 URL. Поисковик видит крошечный сайт. Hreflang alternates есть только для `/` (ru + en), остальные 3 URL без hreflang.

**Fix:** По мере создания SEO-страниц — добавлять в sitemap. Добавить `changefreq` (weekly для лендинга, monthly для legal).

### 1.3 SPA не индексируется

**Impact: HIGH** (уже известно и описано в инструкции)

`/course/#/lesson/5` — всё после `#` невидимо для Яндекса. Единственное, что видит бот — `course/index.html`:
- Title: `"Portugues - Curso de Portugues Europeu"` — **на португальском**, аудитория русская
- Нет meta description
- Нет canonical
- Нет OG tags
- Нет JSON-LD

**Fix:** Обновить `<head>` в `course/index.html` — добавить русский title, description, canonical, OG.

### 1.4 Нет 404 страницы

**Impact: LOW-MEDIUM**

Cloudflare Pages покажет дефолтный 404. Кастомный 404.html с навигацией обратно на сайт — улучшает UX и удержание.

## 2. Technical Foundations

### 2.1 Нет `_headers` файла

**Impact: MEDIUM**

Нет управления cache-control, security headers (X-Frame-Options, CSP, X-Content-Type-Options). Cloudflare Pages поддерживает `_headers` файл.

**Fix:** Создать `_headers` с:
```
/*
  X-Frame-Options: SAMEORIGIN
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin

/images/*
  Cache-Control: public, max-age=31536000, immutable

/*.css
  Cache-Control: public, max-age=604800
```

### 2.2 Два шрифта на лендинге

**Impact: LOW**

Загружаются Geist + JetBrains Mono на лендинге, Inter в курсе. Geist + JetBrains = ~200KB дополнительного трафика. На скорость влияет умеренно (есть `display=swap`).

### 2.3 OG image — .png вместо .webp

**Impact: LOW**

`og:image` указывает на `hero.png`. Социальные сети примут его, но .webp был бы легче. Впрочем, не все платформы поддерживают WebP для OG.

## 5. Расхождения с SEO-инструкцией

### Что аудит нашёл, а инструкция не покрывает

#### 1. robots.txt конфликт с Cloudflare AI Blocker

**Суть:** Cloudflare вставляет свой блок _перед_ вашим. В итоге два `User-agent: *` — ваши `Disallow: /course/js/` и `Disallow: /course/css/` могут игнорироваться парсерами, которые берут только первый блок. `Sitemap:` директива оказывается в самом низу файла.

**Основание:** RFC 9309 (стандарт robots.txt) говорит мержить правила, но реальные парсеры (особенно мелких поисковиков) часто берут первый матч. Яндекс и Google мержат правильно, но лучше не рисковать.

**Инструкция:** Не упоминает вообще — в момент написания Cloudflare ещё не был подключён.

#### 2. FAQPage schema — приоритет выше, чем в инструкции

**Суть:** На лендинге уже есть 5 вопросов-ответов в аккордеоне. Инструкция упоминает Schema.org (`Course`, `FAQPage`, `Organization`), но `Course` и `WebSite` уже добавлены, а `FAQPage` — нет.

**Основание:** FAQPage — один из немногих типов schema, которые Яндекс _реально_ показывает как rich snippet в выдаче (раскрывающиеся вопросы прямо в SERP). Контент уже есть — добавить разметку = 10 минут работы → потенциально удвоение площади сниппета в выдаче.

**Инструкция:** Упоминает, но в одном списке с Organization, без акцента на то, что FAQ-контент готов и это quick win.

#### 3. `/course/index.html` — meta на португальском

**Суть:** Title курса = `"Portugues - Curso de Portugues Europeu"`. Нет description, canonical, OG. Аудитория — русскоязычные.

**Основание:** Даже если SPA-контент не индексируется, сам `/course/` — второй URL в sitemap (priority 0.9). Яндекс заходит на эту страницу и видит title на чужом языке, пустой description. Это сигнал низкого качества.

**Инструкция:** Описывает проблему SPA-индексации (хэш-роуты), но не упоминает, что `<head>` самой SPA-страницы тоже нуждается в оптимизации.

#### 4. Canonical на privacy/terms

**Суть:** Обе страницы без `<link rel="canonical">`.

**Основание:** Без canonical Яндекс может создать дублирующие URL (например, `/privacy` vs `/privacy/` vs `/privacy.html`). Cloudflare Pages иногда отвечает на несколько вариантов URL. Canonical убирает неоднозначность.

**Инструкция:** Не упоминает — legal-страницы рассматриваются как "сделано" после сессии 24.

#### 5. Hreflang неполный

**Суть:** На лендинге есть `hreflang="ru"` и `hreflang="x-default"`, но нет `"en"` и `"uk"`. В sitemap есть ru+en для `/`, но на остальных 3 URL hreflang отсутствует. При этом сайт поддерживает 3 языка.

**Основание:** Неполный hreflang хуже, чем его отсутствие. Яндекс и Google требуют, чтобы hreflang-ссылки были _взаимными_ (страница А ссылается на Б, Б ссылается обратно на А). Если этого нет — hreflang игнорируется, а парсер тратит crawl budget на разбор некорректных сигналов.

**Нюанс:** Поскольку EN/UK версии — это _тот же URL_ с переключением языка через JS (а не отдельные `/en/` страницы), hreflang здесь вообще может быть лишним. Если оставлять — нужно делать правильно. Если убрать — проще и чище.

**Инструкция:** Не упоминает. Hreflang был добавлен в сессии 24, но не проверен на полноту.

#### 6. Twitter Card теги

**Суть:** Нет `twitter:card`, `twitter:title`, `twitter:image`.

**Основание:** Telegram (основной канал продвижения — @ivf_portugal) и VC.ru используют OG-теги и/или Twitter Card для превью ссылок. OG-теги есть, но Twitter Card даёт дополнительный контроль (например, `summary_large_image` для большой картинки). Без них — fallback на OG, который работает, но не оптимально для всех платформ.

**Инструкция:** Не упоминает.

#### 7. `_headers` файл (cache + security)

**Суть:** Нет файла для управления HTTP-заголовками.

**Основание:** Cloudflare Pages поддерживает `_headers` для установки cache-control (ускоряет повторные визиты) и security headers (X-Frame-Options, X-Content-Type-Options). Яндекс учитывает HTTPS-качество как фактор ранжирования, а security headers — часть E-A-T сигналов (Trustworthiness).

**Инструкция:** Не упоминает.

#### 8. 404 страница

**Суть:** Нет кастомного 404.html.

**Основание:** При битых ссылках пользователь видит дефолтный Cloudflare 404 без навигации обратно. Это увеличивает bounce rate (фактор поведенческого ранжирования в Яндексе). Кастомный 404 с ссылкой на главную и курс — удерживает пользователя.

**Инструкция:** Не упоминает.

#### 9. H1 лендинга слишком короткий

**Суть:** `<h1>Европейский португальский</h1>` — два слова, без "курс", "с нуля", "бесплатно".

**Основание:** H1 — один из сильнейших on-page сигналов для Яндекса. Текущий H1 не содержит целевых поисковых запросов ("курс португальского", "с нуля", "бесплатно"). Subtitle "Полная программа с нуля до A2" — это `<p>`, а не часть H1. Поисковик не видит связи.

**Инструкция:** Не анализирует текущий on-page SEO лендинга — фокусируется на будущих SEO-страницах.

#### 10. `meta keywords` переоценён

**Суть:** В инструкции отмечен как достижение (✅ сделано).

**Основание:** Яндекс официально заявил в 2018 году, что `meta keywords` имеет "крайне низкий вес". Google его игнорирует с 2009 года. Не вредит, но и не помогает — не стоит считать это SEO-достижением.

**Инструкция:** Выделен как пункт в этапе 1 и отмечен ✅.

#### 11. Google Search Console

**Суть:** Настроен только Яндекс.Вебмастер.

**Основание:** Даже если фокус на Яндексе, ~30% русскоязычных пользователей используют Google (особенно на мобильных, особенно среди тех, кто переезжает в Португалию — целевая аудитория). Регистрация в GSC бесплатна, занимает 10 минут, даёт дополнительные данные о crawling-ошибках.

**Инструкция:** Не упоминает Google вообще.

#### 12. Core Web Vitals — детализация

**Суть:** Инструкция говорит "проверь PageSpeed, цель выше 70".

**Основание:** Яндекс с 2024 года учитывает LCP, CLS, INP как факторы ранжирования (вслед за Google). "Выше 70 баллов" — слишком абстрактно. Нужны конкретные метрики: LCP < 2.5s, CLS < 0.1, INP < 200ms. Это не просто "оценка", а три отдельных показателя с разными способами оптимизации.

**Инструкция:** Упоминает поверхностно.
